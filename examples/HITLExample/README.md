# HITL (Hardware-In-The-Loop) Example

This example demonstrates how to use Astra-Rocket in HITL simulation mode for desktop testing without deploying to real hardware.

## What is HITL?

Hardware-In-The-Loop testing allows you to run your flight computer code on real hardware (Teensy, STM32, etc.) while feeding it simulated sensor data from a desktop computer. This enables:

- ✅ Rapid iteration on flight algorithms
- ✅ Deterministic, repeatable testing
- ✅ Full system integration testing
- ✅ No risk of hardware damage
- ✅ Debugging with real hardware timing

## Files

- `HITLExample.cpp` - Flight computer firmware (runs on Teensy/STM32)
- `desktop_simulation.py` - Desktop simulation script (runs on PC)
- `README.md` - This file

## Quick Start

### 1. Upload Firmware

Upload `HITLExample.cpp` to your flight computer (Teensy 4.1 or STM32):

```bash
# Using PlatformIO
pio run -e teensy41 -t upload

# Or using Arduino IDE
# Open HITLExample.cpp and upload to board
```

## How It Works

### Communication Protocol

**Desktop → Flight Computer** (HITL packets):
```
HITL/timestamp,ax,ay,az,gx,gy,gz,mx,my,mz,pressure,temp,lat,lon,alt,fix,fixqual,heading
```

Example:
```
HITL/1.234,0.0,0.0,19.62,0.0,0.0,0.0,20.0,10.0,-45.0,101325.0,25.0,45.123,-122.456,100.0,1,8,0.0
```

**Flight Computer → Desktop** (TELEM packets):
```
TELEM/State_FlightStage,State_AltitudeAGL,State_VerticalVelocity,...
```

These are automatically generated by the DataLogger - no extra code needed!

### Simulation Loop

1. Desktop sends `HITL/` packet with simulated sensor data
2. Flight computer parses packet and updates `HITLSensorBuffer`
3. Flight computer calls `astraSys->update(simTime)` with simulation time
4. State estimation, Kalman filter, and flight stage detection run
5. DataLogger automatically outputs `TELEM/` packet
6. Desktop parses telemetry and updates simulation
7. Repeat at 50 Hz

### Flight Computer Code

The HITL-enabled flight computer code is extremely simple:

```cpp
// Enable HITL mode in config
AstraRocketConfig config;
config.withHITL();

AstraRocket rocket(config);
rocket.init();

void loop() {
    rocket.update();  // Handles everything automatically!
}
```

That's it! The `AstraRocket::update()` function detects HITL mode and:
- Waits for `HITL/` packets on Serial
- Parses sensor data via `HITLParser`
- Updates state with simulation time
- Outputs `TELEM/` via DataLogger

## Using OpenRocket CSV Data

**New!** You can now use realistic flight data from OpenRocket simulations:

### 1. Export from OpenRocket

In OpenRocket:
1. Run your simulation
2. Go to **Plot/Export** → **Export data**
3. Select **All variables** or at minimum: Time, Altitude, Velocity, Acceleration, Pressure, Temperature
4. Export as CSV

### 2. Run with CSV file

```bash
# Linux/Mac
python desktop_simulation.py /dev/ttyACM0 your_rocket.csv

# Windows
python desktop_simulation.py COM3 FMMORK.csv
```

The script automatically:
- Converts feet → meters
- Converts °F → °C
- Converts r/s → rad/s
- Interpolates data to 50Hz
- Handles missing columns with sensible defaults

### Modify Flight Profile (Physics Mode)

For the built-in physics simulation, edit `desktop_simulation.py` and adjust rocket parameters:

```python
# In RocketSimulation.__init__()
self.mass = 5.0           # Rocket mass (kg)
self.motor_thrust = 150.0  # Motor thrust (N)
self.motor_burnout = 2.5   # Burn time (s)
self.drag_coeff = 0.3      # Drag coefficient
```

### Add Sensor Noise

Add realistic sensor noise in `get_sensor_data()`:

```python
# Add noise to accelerometer
accel_body += np.random.normal(0, 0.1, 3)  # 0.1 m/s² noise

# Add noise to pressure
pressure += np.random.normal(0, 10.0)  # 10 Pa noise
```

### Test Edge Cases

Modify the simulation to test failure scenarios:

```python
# GPS dropouts
if 5.0 < state.time < 7.0:
    sensor_data['gps_fix'] = 0

# Sensor saturation
if np.linalg.norm(accel_body) > 100:
    accel_body = accel_body / np.linalg.norm(accel_body) * 100
```

## Troubleshooting

### "Port already in use"

Close any serial monitors (Arduino IDE, PlatformIO, etc.) before running the simulation.

### "No response from flight computer"

1. Check baud rate matches (115200)
2. Verify correct serial port
3. Upload the HITL firmware
4. Press reset button on flight computer

### "Parse errors"

Make sure the HITL packet format matches exactly. The parser expects 18 comma-separated values.
